# ソースと配布版・検証の見方

## 三つの配布先

| 配布物 | 元のコード | 更新経路 |
|---|---|---|
| Web | `src/`・`shared/` | 静的ビルドした `out/` をCloudflareで配信 |
| バックエンド | `convex/`・`shared/` | 専用Convexへの配備 |
| Chrome拡張 | `extension/`・`src/`の共有UI・`shared/` | 拡張ビルド、パッケージ作成、ストア審査と配布 |

GitHubのmainにあるコードだけを見て、三つの配布先すべてに同じ版が届いたとは判断できません。APIで運営キーを使う生成はConvex、本人キーを使う生成はWebまたは拡張に組み込んだプロンプトで動きます。

## 読者が確認できること

```sh
git rev-parse HEAD
npm ci
npm run typecheck
npm test
```

プロンプト原稿と生成済み定数の一致、認証・本人以外の操作の拒否、残数の予約と返却、決済の二重加算防止、退会、接続権限などを模擬テストで確認できます。外部AIの実回答の品質、実カードの決済、外部サービス側の設定は、これらのテストとは別の確認です。

拡張のビルドは `extension/sidepanel.js` と `dist/extension/` を上書きします。比較用の別コピーで行い、使用した `NEXT_PUBLIC_CONVEX_SITE_URL` とNode.jsの版を揃えてください。既存の審査提出ZIPを書き換える必要はありません。

## 配布時に残す対応情報

今後の配布記録には、Web・Convex・拡張を分けて次を残します。未確認の欄を成功扱いにせず、秘密・アカウント識別子を記録しません。

| 項目 | 記録する情報 |
|---|---|
| ソース | 対象コミットと配布に使ったファイルの範囲 |
| 検証 | 実行した検査と結果、模擬／実環境の区別 |
| Web | ビルド元コミット、配備日時、公開URL、配信を確認した結果 |
| Convex | 配備したソースコミット、配備日時、確認した機能と未確認の範囲 |
| 拡張 | Manifestの版、ZIPのSHA-256、審査提出日、公開を確認した日時 |
| プロンプト | Engine原稿とConstitutionの採用版 |

ソースの閲覧可能性と配布物の一致を区別することで、確認できた範囲を利用者が追えるようにします。
