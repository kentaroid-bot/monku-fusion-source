# 安全設計と検証範囲

[データの送信先・保存・削除](data-handling.md) / [問題の非公開連絡先](../SECURITY.md) / [版と検証の見方](source-and-releases.md)。以下はリポジトリ内の設計であり、本番配布版との一致や第三者監査を表すものではありません。

- 外部公開はHTTPルートのみ。DB操作と決済Actionはinternal。旧ai.convert/transformations.saveを廃止。
- 匿名walletは暗号学的ランダムな256bit秘密トークンで認証。DBはSHA-256のみ保持。任意userIdでは操作不可。JWTログインや本人確認ではない。
- 端末追加は256bitコードを10分・1回限りで交換。コード・トークンをURLやログに出さない。HTTPSのみ。
- 0.3.0のアカウント連携はWebのClerk本人確認と明示した権限選択を必要とする。トークンは30日で失効し、本人のWeb接続一覧または拡張自身から解除できる。旧残数トークンにアカウント権限を自動追加しない。連携トークンからの再委任・端末管理・退会・アカウント紐付けを拒否する。
- 初回はTurnstile。全体100登録/日、操作種類ごと全体1000/日・財布ごと6/分。全体上限で費用を制限する。IP偽装可能なヘッダーを認証に使わない。
- 残数予約、完了、返却、決済加算をConvexトランザクションで処理。処理IDは財布と入力ハッシュに結び、同じIDの重複生成を禁止。返却は一度だけ、予約3分後にも実行。24時間後に私的結果を削除。
- StripeのWebhook署名必須。通知のsessionをStripeから再取得し、paid/payment/100JPY/専用商品/10回分を確認。決済確認画面ではwalletも一致させる。戻りURLはサーバー固定。API秘密はサーバー限定。
- 入力を4000文字、結果を各2000文字に制限。定型的な個人情報を伏せ字にしてから安全判定。Jevが危険と判定した場合は拒否。未設定・失敗・判定形式不正ではGeminiで代替確認し、それも失敗・不正なら拒否。入力とサーバー生成の出力、公開直前の本文を確認。AI検出の完全性は保証しない。
- 原文はDB保存しない。公開は明示同意、生成結果と本人が確認・編集した動機、モード、ジャンルのみ。公開フラグのない旧記録は非公開。本人は公開直後または自分の投稿一覧から取り下げ可能。匿名の公開一覧は直近5件。本人確認済みの一覧は20件ずつページ送りし、私的な所有者識別子を返さない。いいねは本人だけが閲覧・変更できる。
- 拡張は選択テキストだけ受け取る。永続化せずsession領域に一時保存。APIキーと接続トークンはtrusted extension contextsのみに制限。GoogleキーはURLに入れずヘッダーで送信。画面描画はtextContent/Reactエスケープ。

## 残る運用条件

公開前に実環境・テスト決済・実機拡張・申請表示を確認する。匿名walletは接続トークンを紛失すると自動復旧できず、盗まれると残数利用の権限を持つ。ログインへ紐付けた残数は別ブラウザから利用できる。0.3.0の一覧・解除は明示的にアカウント連携した拡張だけが対象で、旧匿名接続の一括管理は含まない。チャージバック自動調整・購入履歴画面は未実装。退会後に完了した決済は返金処理へ回す。それ以外の返金は運営者がStripe上で扱い、残数との整合を確認する。自動無料枠の厳密な一人一回保証はなく、Turnstileと全体上限で抑制する。

APIの運用停止、秘密・接続情報の失効、既存環境からの移行は個別の運用操作。今回の修正だけで既存のデプロイ環境が修復されたとは扱わない。
